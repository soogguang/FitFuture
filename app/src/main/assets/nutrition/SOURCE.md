# 식약처 음식 영양 DB

- 제공처: 식품의약품안전처, K-FIND 식품영양성분 데이터베이스
- 자료: 음식 DB, 2026-08-28 버전 (확인/다운로드: 2026-11-19)
- 공식 다운로드 안내: https://various.foodsafetykorea.go.kr/nutrient/general/down/historyList.do
- 원본 다운로드 항목 ID: `1787898710194`, DB 구분 `02`
- 원본 XLSX SHA-256: `1ef3551f9a1d0ee87891d6306fa22bbd6a7ffcc90f2c70a4a184dbfe3fce6ea6`

`mfds-foods.tsv`는 원본에서 **기준량이 정확히 100g이고 열량·탄수화물·단백질·지방이 모두 있는 2,696개 행**만 추출한 자료다.
100ml를 100g으로 간주하지 않으며 결측값을 0으로 채우지 않는다. 모든 음식/원재료/가공식품을 포함하지 않는다.

TSV 열: 식품코드, 식품명, 식품기원명, kcal/100g, 탄수화물 g/100g, 단백질 g/100g, 지방 g/100g.
동일한 이름은 외식 분석값 → 가정식 분석값 → 기타 분석값 → 산출값, 같은 우선순위에서는 식품코드 순으로 첫 행을 사용한다.
원본 이름/코드와 수치는 보존하며 평균을 내거나 생성형 모델로 결측값을 만들지 않는다.

음식명은 공백과 `_`만 정규화하며, `aliases.tsv`에 명시한 동의어만 추가 연결한다 (예: 짜장면 → 자장면, 연어초밥 → 초밥_연어).
앱(`NutritionDatabase`)과 추천 서버(`fitfuture/foodnames.py`)가 이 TSV와 동의어 파일을 함께 읽으므로 두 쪽의 매칭 결과가 같다.
동의어는 대표 변형이 분명할 때만 추가하고, 이미 DB에 있는 정확한 이름을 가리지 않는다 (서버 테스트가 검사).
예: 돼지국밥 → 국밥_돼지고기 (`D301-004140000-0001`), 100g당 76kcal, 탄수화물 6.23g, 단백질 5.53g, 지방 3.22g.
국밥의 DB 값은 해당 국밥 전체의 값이며 별도 밥을 입력하면 별도로 더해진다. 실제 구성과 섭취량을 확인해야 한다.

재생성: 공식 사이트에서 해당 버전 XLSX를 다운로드한 뒤 `python scripts/import_mfds.py 원본.xlsx` 실행.
원본 파일은 빌드 폴더에만 보관하며 저장소에 넣지 않는다. 앱 결과 화면에 제공처·버전·매칭 식품명·코드를 표시한다.

조리법/재료가 다르면 실제 영양성분과 차이가 날 수 있다. 조회 실패 시 전체 합계를 생성하지 않고 해당 음식명을 표시한다.
